# 备份与数据完整性

可恢复的备份 = **原始媒体** + **数据库快照**。缩略图、索引和模型缓存可以重建，不是备份对象。

## 创建数据库备份

在**设置 → Server → 数据库备份**：

1. 可启用自动备份（默认 24 小时一次、保留 14 份），或点击**立即创建**。
2. **下载快照到另一块设备**。同磁盘的备份防不了磁盘故障。

**成功标志**：备份列表出现新快照，可下载。
**数据边界**：快照只含 SQLite 目录数据（相册、人物、编辑记录、账户），**不含媒体文件**。

## 原始媒体备份

- 至少保留两份，其中一份不与主设备长期连接；
- 按[理解资源库与原始文件](./repositories)把资源库目录整体复制；
- 定期做一次真实恢复演练，而不是只看备份任务显示“成功”。

::: danger 不要复制运行中的数据库
直接复制正在使用的 `library.sqlite3` 可能得到损坏快照。用应用内的备份功能；必须离线复制时，先完全退出 Desktop 或停止 Server。
:::

## 恢复数据库

在**设置 → Server → 数据库备份**选择快照，点击**恢复**。

**点击恢复只是提交请求**（服务器返回 `202 Accepted` 和 operation ID），恢复要经过：

```text
暂存 → 重启 → 安装 → 验证 → 完成
                       └→ 回滚 / 失败
```

- **页面短暂断线是正常现象**：重启期间连接会断开，别反复刷新或重复提交；
- 记录 operation ID，页面恢复后可凭它继续观察同一操作；
- **验证失败时旧数据库会自动恢复**，不会停在半坏状态；
- 恢复期间不要关闭容器、删除媒体目录或再次点击恢复。

**前置条件**：恢复前先创建最新恢复点，确认没有导入/编辑任务在运行，并确认对应时点的媒体备份仍然存在。

## 常见误区

- 回收站不是备份；RAID、同步盘、云盘各有局限，不能替代独立验证过的备份；
- 数据库备份 ≠ 媒体备份，两者都要有；
- 同磁盘备份不能抵御磁盘故障。

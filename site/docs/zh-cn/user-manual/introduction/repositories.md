# 理解资源库与原始文件

Lumilio 把**存储位置**和**资源库**分成两层：

- **存储位置**是被授权使用的父目录，用 `.lumilioroot` 标记身份。一个存储位置可以包含多个资源库。
- **资源库**是独立的媒体集合，用 `.lumiliorepo` 标记身份并记录存储策略。原始媒体文件就放在资源库内。

<RepositoryTree />

::: warning 隐藏文件与目录
`.lumilioroot`、`.lumiliorepo` 以及 `.lumilio/` 是隐藏文件与目录，默认情况下不可见。可以在 Windows、macOS 或 Linux 的文件管理器中开启显示隐藏文件来查看。
:::

资源库内的目录分为两类：

- **`inbox/`**：上传和云导入的文件由 Lumilio 自动归档到这里，归档路径由存储策略决定。

::: danger 不要手动操作 inbox
`inbox/` 中的文件由 Lumilio 的暂存和提交管道管理。不要在文件管理器中向 `inbox/` 添加、移动、重命名或删除文件——这会导致数据库记录与实际文件不一致。
:::

- **自由区**：`inbox/` 和 `.lumilio/` 以外的目录。你可以像使用普通文件夹一样在这里组织媒体文件，扫描会原地登记它们。

在自由区中添加、移动或删除文件后，执行**重新扫描**让 Lumilio 同步数据库记录。例如，把一批媒体从 `旅行/` 移到 `2024旅行/` 后，重新扫描会更新对应的路径。

存储策略的区别、`.lumilio/` 的完整结构和回收站等细节，请参阅[存储细节](../help/storage-details)。

::: info 数据库不在这棵树里
相册、人物、账户和任务等数据保存在应用状态目录的 SQLite 数据库中。密钥、云会话和数据库备份也在资源库之外。因此备份资源库目录并不等于完成了整套备份。参见[备份与数据完整性](./integrity)。
:::

## 存储位置与资源库的挂载和创建

::: danger 使用前必读
当前版本创建资源库后，不能修改资源库名称、存储策略或重名文件处理方式，也不能从 Lumilio 中删除资源库。创建前请先确认名称和策略。

普通资源库的**名称同时就是目录名称**。Lumilio 不会自动转成小写，也不会把空格改成连字符。例如输入 `Family Media`，目录就是 `Family Media`，不会变成 `family-media`。

名称长度为 1–80 个字符，并且只能使用：

- 中文等文字；
- 数字；
- 半角空格；
- 半角连字符 `-`；
- 下划线 `_`。

名称不能以空格开头或结尾。`/`、`\`、`.`、`:`、括号和其他符号均不允许。大小写会原样保留；同一存储位置中也不能同时创建只有大小写不同的名称。

主资源库是唯一例外：首次设置时填写的名称用于界面显示，但它的目录固定为 `primary`。
:::

### Desktop

Desktop 可以使用多个存储位置。默认位置由 Desktop 管理；首次设置完成后，还可以在控制面板中添加外接硬盘或网络卷。每个存储位置都有自己的 `.lumilioroot`，并且可以包含多个资源库。

要在一个新位置创建资源库：

1. 打开 **Desktop 控制面板**，添加一个准备长期使用的父目录作为存储位置。例如选择外接硬盘中的 `Lumilio/`，而不是某个具体资源库目录。
2. 回到浏览器中的**管理**页面，选择**创建资源库**。
3. 选择刚登记的存储位置，填写资源库名称并确认存储策略。
4. Lumilio 在 `<存储位置>/<资源库名称>/` 中创建 `.lumiliorepo` 和 `.lumilio/`。
5. 创建成功后，再通过上传、扫描或云导入加入媒体。

如果目录已经包含有效的 `.lumiliorepo`，应在 Desktop 控制面板中使用连接已有资源库的流程。不要把普通的非空目录当作新资源库直接创建。

### Server

Server 整个实例只有 Compose 挂载到 `/data/storage` 的一个存储位置，也就是一个 `.lumilioroot`。Web 主界面不能添加第二个存储位置；增加第二块物理磁盘时，应把它挂载为 `/data/storage` 下的一个**资源库子目录**。

先区分 Compose 挂载的两端：

```text
<宿主机目录 A>:/data/storage/<资源库名称 B>
```

- **宿主机目录 A**只由 Linux、NAS 和 Docker 使用。它不参与 Lumilio 的名称校验，可以叫 `/mnt/disk-2/Lumilio-A-xxx`。
- **资源库名称 B**是容器内的目录名。它必须符合上面的白名单，并且必须与稍后在 Web 界面输入的资源库名称完全相同，包括大小写和空格。

下面以 `家庭媒体` 为资源库名称：

1. 在宿主机或 NAS 上准备一个**空目录**：

   ```bash
   mkdir -p /mnt/disk-2/Lumilio-A-xxx
   ```

2. 在 `compose.yml` 的 `lumilio` 服务中保留 `/data/storage` 的原有挂载，再增加资源库子挂载：

   ```yaml
   services:
     lumilio:
       volumes:
         - type: bind
           source: ${LUMILIO_STORAGE:-./lumilio/media}
           target: /data/storage
         - type: bind
           source: /mnt/disk-2/Lumilio-A-xxx
           target: /data/storage/家庭媒体
           bind:
             create_host_path: false
   ```

3. 应用新的 Compose 配置：

   ```bash
   docker compose up -d
   ```

   不要只运行 `docker compose restart`；它不会应用新增的挂载配置。

4. 打开 Web 主界面的**管理**页面，创建资源库并准确输入：

   ```text
   家庭媒体
   ```

5. Lumilio 会直接在已经挂载的空目录中创建 `.lumiliorepo`、`.lumilio/` 和 `inbox/`。创建成功后，宿主机上的实际内容位于 `/mnt/disk-2/Lumilio-A-xxx`。
6. 最后再通过文件系统、上传或云导入加入媒体。通过文件系统放入的媒体应位于 `inbox/` 和 `.lumilio/` 之外，随后执行重新扫描。

::: warning 必须先挂载，再创建
Bind mount 不会把容器目录中已有的文件复制到宿主机。先创建资源库、再把空目录挂载到同一路径，会遮住原来的 `.lumiliorepo` 和 `.lumilio/`，造成资源库离线。

如果第 2 步写成 `/data/storage/家庭媒体`，第 4 步就必须输入 `家庭媒体`。输入 `家庭媒体库`、`家庭媒体 ` 或不同大小写，都会指向另一个目录或直接校验失败。
:::

::: warning 创建目标必须为空且可写
创建请求会先校验名称，再确认目标目录为空并尝试写入。目录非空、只读、权限不足或磁盘空间不足时，创建会立即失败，不会登记一个不完整的资源库。
:::

## 注意事项

- **不要手动修改** `.lumilioroot` 或 `.lumiliorepo` 标记文件。移动资源库时使用控制面板的连接流程。
- **不要重命名资源库目录**：当前版本不会跟随手工改名，资源库会显示为离线。
- **不要手动操作 `inbox/`**：`inbox/` 由 Lumilio 管道管理，手动添加、移动、重命名或删除会导致数据库与文件不一致。
- **自由区改动后需重新扫描**：在 `inbox/` 和 `.lumilio/` 以外添加、移动或删除文件后，执行重新扫描同步数据库。
- **移除外接硬盘前**，先确认没有正在运行的后台任务。
- **备份**要同时覆盖媒体目录和数据库。应用内的数据库备份只包含相册、人物等目录数据，不含媒体原件。
- **存储策略**只影响上传和云导入的归档路径，不影响扫描。
- **运行 Lumilio 的系统账户**必须能读取资源库；上传和内部管理还需要写入权限。

如果磁盘挂载点或 Windows 盘符变化，重新添加同一存储位置并选择"重新连接到此处"。只有确认是同一块已移动的磁盘时才这样做。

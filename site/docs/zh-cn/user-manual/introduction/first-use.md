# 完成首次设置

首次设置的入口取决于部署类型：

| 部署类型 | 从哪里开始 | 何时进入 Web 主界面 |
| --- | --- | --- |
| Desktop | Desktop 控制面板 | 控制面板完成设置并启动本机服务后 |
| Server | 当前可访问的 Server 地址 | Server 就绪后直接打开 |

两条路径进入 Web 主界面后会汇合，共同完成管理员、安全设置和主资源库创建。

## Desktop

Desktop 第一次启动时会打开**控制面板**，并以首次设置向导的形式显示。完成这部分设置后，控制面板才会启动本机 Server。

### 完成控制面板向导

控制面板共有三步。

#### 第一步：确认本机存储与条款

1. 查看本机默认存储位置，确认它可以写入并有足够的剩余空间。
2. 选择下载地区。
3. 阅读使用条款和开源许可，然后确认接受。

这里显示的是 Desktop 管理的默认存储位置。首次设置期间只能查看，不能改到外接磁盘或网络位置。完成全部首次设置后，可以在控制面板中添加其他存储位置。

“下载地区”只决定 Desktop 管理的程序、Lumen AI 和模型从 GitHub 直接下载，还是通过中国大陆镜像下载。它不会改变媒体存放位置，也不同于稍后在 Web 主界面选择的地区偏好。

#### 第二步：选择 Lumen AI 计算后端

选择适合这台电脑的后端，或选择**稍后设置**。推荐项会根据当前系统与硬件预先选中。

Lumen AI 是可选能力。稍后设置不会影响媒体的导入、浏览、播放和基础整理；完成首次设置后仍可在控制面板中启用。

#### 第三步：选择 Lumen AI 能力

如果决定现在配置 Lumen AI：

1. 选择能力预设；
2. 查看预计需要的内存和磁盘空间；
3. 确认模型缓存位置；
4. 选择完成并安装。

所选模型会在设置完成后于后台下载。也可以选择**稍后设置**，不在此时安装 Lumen AI。

### 等待本机服务启动

完成控制面板向导后：

1. 控制面板切换到本机运行状态页面；
2. Lumilio Server 开始启动；
3. 服务就绪后，默认浏览器自动打开 `http://localhost:6680`。

如果浏览器没有自动打开，请等待控制面板中的 Server 状态变为“运行中”，然后选择**在浏览器中打开**。

看到“首次运行设置”欢迎页面后，继续[在 Web 主界面完成共同设置](#在-web-主界面完成共同设置)。

## Server

Server 没有 Desktop 控制面板。开始前应已按照[安装 Lumilio Photos](./installation)完成 Docker 部署。

### 确认 Server 已就绪

在部署目录中查看状态：

```bash
docker compose ps
```

`lumilio` 服务应显示为健康状态。如果尚未就绪，请先查看日志并解决启动错误，不要在浏览器中反复刷新首次设置页面。

### 打开当前部署地址

默认 Compose 可以直接通过 Linux 主机的局域网地址访问，例如：

```text
http://192.168.1.20:6680
```

如果已经配置域名、反向代理或 HTTPS，也可以使用对应地址。首次设置不要求域名或 HTTPS；密码和 TOTP 在局域网 HTTP 地址上仍可设置，但远程浏览器不能登记通行密钥。

看到“首次运行设置”欢迎页面后，继续下面的共同流程。

## 在 Web 主界面完成共同设置

下面的步骤对 Desktop 和 Server 相同。

### 选择语言与地区

欢迎页面会显示当前访问地址，并要求选择 Web 主界面的语言和地区。这里的选择属于当前浏览器中的使用偏好；Desktop 用户此前选择的“下载地区”则用于控制面板管理的下载，两者用途不同。

确认地址正确后，选择**开始设置**。

### 创建管理员

第一个账户是管理员，可以管理 Server、资源库、用户和运行设置。

填写用户名和两次密码：

- 用户名长度为 3–32 个字符，必须以英文字母开头；
- 用户名可以使用小写英文字母、数字、点号、下划线和连字符；
- 密码长度为 10–72 个字符；
- 密码至少包含一个大写字母、一个小写字母和一个数字。

建议使用只用于当前 Lumilio 实例的独立密码。选择**创建管理员并继续**后，系统会登录这个新账户并进入安全设置。

### 设置账户安全

创建账户后，向导依次提供以下安全设置：

```text
验证器应用（TOTP）
    ├─ 暂时跳过 → 仅使用密码 → 创建主资源库
    └─ 验证并启用
          ├─ 可选：登记通行密钥
          └─ 保存恢复代码 → 创建主资源库
```

::: warning 建议启用多因素验证
向导允许跳过全部多因素验证，但管理员账户可以管理用户、资源库和 Server。长期保存媒体或允许网络访问的实例，建议完成 TOTP 设置，并把恢复代码保存在与 Lumilio 运行设备分离的安全位置。
:::

#### 验证器应用（TOTP）

使用验证器应用扫描二维码，或者手动输入页面显示的密钥。然后输入应用生成的 6 位验证码，选择**验证并启用**。

也可以选择**暂时跳过**。跳过 TOTP 会同时跳过通行密钥和恢复代码，管理员账户暂时只使用密码登录，之后可以在账户设置中补充。

::: tip 什么是 TOTP？
**我们强烈建议你启用 TOTP 多因素验证**

TOTP 是一种基于时间的一次性密码算法。启用后，登录时除了密码，还需要输入验证器应用生成的 6 位验证码。

常见的验证器应用包括：

- [Apple“密码”](https://support.apple.com/zh-cn/guide/iphone/ipha6173c19f/ios)
- [Microsoft Authenticator](https://support.microsoft.com/zh-cn/authenticator/download-microsoft-authenticator)
- 腾讯身份验证器
- [Google Authenticator](https://play.google.com/store/apps/details?id=com.google.android.apps.authenticator2&hl=zh-CN)
- 1Password、Bitwarden 等密码管理器
:::

#### 通行密钥

启用 TOTP 后，如果当前浏览器和访问地址支持通行密钥，向导会询问是否登记一个管理员通行密钥。可以使用设备解锁、指纹、面容或硬件安全密钥完成登记，也可以暂时跳过。

::: tip 什么是通行密钥？
***非必要时，你不需要启用通行秘钥，它涉及 HTTPS 与 WebAuthn 等进阶特性。***

通行密钥使用生物识别、设备 PIN 码或硬件安全密钥确认身份。它基于公钥密码学，Lumilio Server 不会保存可用于登录的私钥。

支持通行密钥的设备和应用通常包括：

- 支持 Touch ID 或 Face ID 的 Apple 设备（使用 iCloud 钥匙串）；
- 支持指纹或面部识别的 Android 设备（使用 Google 密码管理器）；
- 支持 Windows Hello 的设备；
- YubiKey 等硬件安全密钥；
- 1Password、Bitwarden 等第三方密码管理器。
:::

::: warning 通行密钥需要安全连接
通行密钥仅在支持 [WebAuthn](https://developer.mozilla.org/zh-CN/docs/Web/API/Web_Authentication_API#%E6%B5%8F%E8%A7%88%E5%99%A8%E5%85%BC%E5%AE%B9%E6%80%A7) 的浏览器中可用。访问地址必须是 Desktop 本机的 `http://localhost`，或者具有可信证书的 `https://` 地址。

普通局域网 HTTP 地址不能登记或使用通行密钥。如果需要从其他设备使用通行密钥，请先阅读[HTTPS 与通行密钥](../help/https)，确定正式的 HTTPS 地址后再登记。
:::

#### 恢复代码

启用 TOTP 后，向导会显示一组一次性恢复代码。请下载、复制或记录这些代码，并保存在与运行 Lumilio 的设备分离的安全位置。

每个恢复代码只能使用一次。当密码之外的验证方式全部丢失时，它们是恢复管理员访问的重要备用方式。确认已经保存后，才能继续创建主资源库。

### 创建主资源库

主资源库是当前实例必须存在的第一个资源库。填写：

1. **名称**：用于在 Web 主界面中识别这个资源库；
2. **存储策略**：决定上传和云导入的媒体如何排列；
3. **重复文件处理**：决定目标目录中出现同名文件时如何处理。

存储根目录由 Desktop 或 Server 配置提供，在这里是只读的。主资源库会创建在：

```text
<存储根目录>/primary
```

名称长度为 1–80 个字符，只能使用文字、数字、半角空格、半角连字符 `-` 和下划线 `_`，并且不能以空格开头或结尾。主资源库的目录固定为 `primary`，因此这里填写的名称只用于界面显示；以后创建普通资源库时，名称会同时成为实际目录名。

如果暂时不确定如何选择存储策略和重复文件处理，可以保留界面的预选值。不同策略的具体行为见[存储细节](../help/storage-details)。

Desktop 首次设置不能把主资源库创建在外接磁盘上。完成设置后，可以先在 Desktop 控制面板添加其他存储位置，再从 Web 主界面创建普通资源库。Server 的存储根目录则由 Compose 中的媒体目录挂载决定。

选择创建后，系统会打开 Web 主界面。

## 验证首次设置

使用少量已有备份的测试媒体验证整个流程：

1. 打开**管理**，确认主资源库处于可用状态；
2. 加入少量图片、视频或音频；
3. 打开**状态**，等待后台处理任务稳定；
4. 返回**资源库**，确认媒体可以打开，视频和音频可以播放；
5. 抽查文件名、时间和其他元数据是否正确。

如果设置没有完成，不要手动创建或反复删除 `primary` 目录：

- Desktop 用户先查看控制面板中的 Server 状态和错误日志；
- Server 用户查看对应 Compose 服务的日志；
- 确认问题属于管理员未创建、主资源库缺失，还是存储路径不可写。

验证完成后，继续阅读[理解资源库与原始文件](./repositories)。

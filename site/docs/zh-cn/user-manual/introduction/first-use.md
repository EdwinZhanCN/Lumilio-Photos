# 完成首次设置

首次设置的入口取决于部署类型：

| 部署类型 | 从哪里开始 | 何时进入 Web 主界面 |
| --- | --- | --- |
| Desktop | Desktop 控制面板 | 控制面板完成设置并启动本机服务后 |
| Server | 最终的 HTTPS 部署地址 | Server 就绪后直接打开 |

两条路径进入 Web 主界面后会汇合，共同完成管理员、安全设置和主资源库创建。

## Desktop

Desktop 第一次启动时会打开**控制面板**，并以首次设置向导的形式显示。完成这部分设置后，控制面板才会启动本机 Server。

### 完成控制面板向导

控制面板共有三步。

#### 第一步：确认本机存储与条款

1. 查看本机默认存储位置，确认它可以写入并有足够的剩余空间。
2. 选择下载地区。
3. 阅读使用条款和开源许可，然后确认接受。

这里显示的是 Desktop 管理的默认存储位置。首次设置期间只能查看，不能改到外接磁盘或网络位置。完成全部首次设置后，可以在控制面板中添加其他存储位置。

“下载地区”只决定 Desktop 管理的程序、Lumen 和模型从 GitHub 直接下载，还是通过中国大陆镜像下载。它不会改变媒体存放位置，也不同于稍后在 Web 主界面选择的地区偏好。

#### 第二步：选择 Lumen 计算后端

选择适合这台电脑的后端，或选择**稍后设置**。推荐项会根据当前系统与硬件预先选中。

Lumen 是可选能力。稍后设置不会影响媒体的导入、浏览、播放和基础整理；完成首次设置后仍可在控制面板中启用。

#### 第三步：选择 Lumen 能力

如果决定现在配置 Lumen：

1. 选择能力预设；
2. 查看预计需要的内存和磁盘空间；
3. 确认模型缓存位置；
4. 选择完成并安装。

所选模型会在设置完成后于后台下载。也可以选择**稍后设置**，不在此时安装 Lumen。

### 等待本机服务启动

完成控制面板向导后：

1. 控制面板切换到本机运行状态页面；
2. Lumilio Server 开始启动；
3. 服务就绪后，默认浏览器自动打开 `http://localhost:6680`。

如果浏览器没有自动打开，请等待控制面板中的 Server 状态变为“运行中”，然后选择**在浏览器中打开**。

看到“首次运行设置”欢迎页面后，继续[在 Web 主界面完成共同设置](#在-web-主界面完成共同设置)。

## Server

Server 没有 Desktop 控制面板。开始前应已按照[安装 Lumilio Photos](./installation)完成 Docker 部署。

### 确认 Server 已就绪

使用部署时选择的 Compose 文件查看状态。例如：

```bash
docker compose -f compose.caddy.yml ps
```

`lumilio` 服务应显示为健康状态。如果尚未就绪，请先查看日志并解决启动错误，不要在浏览器中反复刷新首次设置页面。

### 打开最终 HTTPS 地址

在浏览器中打开部署时配置的最终地址，例如：

```text
https://media.example.com
```

不要使用临时 IP 地址或另一个主机名开始设置。最终 HTTPS 地址同时决定通行密钥使用的 Origin；更换主机名后，需要在新地址重新登记通行密钥。

看到“首次运行设置”欢迎页面后，继续下面的共同流程。

## 在 Web 主界面完成共同设置

下面的步骤对 Desktop 和 Server 相同。

### 选择语言与地区

欢迎页面会显示当前访问地址，并要求选择 Web 主界面的语言和地区。这里的选择属于当前浏览器中的使用偏好；Desktop 用户此前选择的“下载地区”则用于控制面板管理的下载，两者用途不同。

确认地址正确后，选择**开始设置**。

### 创建管理员

第一个账户是管理员，可以管理 Server、资源库、用户和运行设置。

填写用户名和两次密码：

- 用户名长度为 3–32 个字符，必须以英文字母开头；
- 用户名可以使用小写英文字母、数字、点号、下划线和连字符；
- 密码长度为 10–72 个字符；
- 密码至少包含一个大写字母、一个小写字母和一个数字。

建议使用只用于当前 Lumilio 实例的独立密码。选择**创建管理员并继续**后，系统会登录这个新账户并进入安全设置。

### 设置账户安全

安全设置按以下顺序进行：

```text
验证器应用（TOTP）
    ├─ 暂时跳过 → 仅使用密码 → 创建主资源库
    └─ 验证并启用
          ├─ 可选：登记通行密钥
          └─ 保存恢复代码 → 创建主资源库
```

#### 验证器应用（TOTP）

使用验证器应用扫描二维码，或者手动输入页面显示的密钥。然后输入应用生成的 6 位验证码，选择**验证并启用**。

TOTP 是一种随时间变化的一次性验证码。常见的验证器包括 Apple“密码”、Microsoft Authenticator、Google Authenticator、1Password 和 Bitwarden。

也可以选择**暂时跳过**。跳过 TOTP 会同时跳过通行密钥和恢复代码，管理员账户暂时只使用密码登录，之后可以在账户设置中补充。

#### 通行密钥

启用 TOTP 后，如果当前浏览器和访问地址支持通行密钥，向导会询问是否登记一个管理员通行密钥。可以使用设备解锁、指纹、面容或硬件安全密钥完成登记，也可以暂时跳过。

通行密钥要求当前地址是：

- Desktop 本机的 `http://localhost`；或者
- 具有有效证书的 `https://` 地址。

普通局域网 HTTP 地址不能登记或使用通行密钥。需要从其他设备访问 Desktop 时，请先阅读[HTTPS 与通行密钥](../help/https)。

#### 恢复代码

启用 TOTP 后，向导会显示一组一次性恢复代码。请下载、复制或记录这些代码，并保存在与运行 Lumilio 的设备分离的安全位置。

每个恢复代码只能使用一次。当密码之外的验证方式全部丢失时，它们是恢复管理员访问的重要备用方式。确认已经保存后，才能继续创建主资源库。

::: warning 建议为管理员启用多因素验证
界面允许跳过 TOTP，但管理员能够管理用户、资源库和 Server。长期保存媒体或允许网络访问的实例，建议启用 TOTP、按需登记通行密钥，并妥善保存恢复代码。
:::

### 创建主资源库

主资源库是当前实例必须存在的第一个资源库。填写：

1. **名称**：用于在 Web 主界面中识别这个资源库；
2. **存储策略**：决定上传和云导入的媒体如何排列；
3. **重复文件处理**：决定目标目录中出现同名文件时如何处理。

存储根目录由 Desktop 或 Server 配置提供，在这里是只读的。主资源库会创建在：

```text
<存储根目录>/primary
```

如果暂时不确定如何选择存储策略和重复文件处理，可以保留界面的预选值。不同策略的具体行为见[存储细节](../help/storage-details)。

Desktop 首次设置不能把主资源库创建在外接磁盘上。完成设置后，可以先在 Desktop 控制面板添加其他存储位置，再从 Web 主界面创建普通资源库。Server 的存储根目录则由部署时的持久化挂载和 TOML 配置决定。

选择创建后，系统会打开 Web 主界面。

## 验证首次设置

使用少量已有备份的测试媒体验证整个流程：

1. 打开**管理**，确认主资源库处于可用状态；
2. 加入少量图片、视频或音频；
3. 打开**状态**，等待后台处理任务稳定；
4. 返回**资源库**，确认媒体可以打开，视频和音频可以播放；
5. 抽查文件名、时间和其他元数据是否正确。

如果设置没有完成，不要手动创建或反复删除 `primary` 目录：

- Desktop 用户先查看控制面板中的 Server 状态和错误日志；
- Server 用户查看对应 Compose 服务的日志；
- 确认问题属于管理员未创建、主资源库缺失，还是存储路径不可写。

验证完成后，继续阅读[理解资源库与原始文件](./repositories)。

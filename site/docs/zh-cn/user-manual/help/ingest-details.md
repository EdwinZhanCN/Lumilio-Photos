# 导入与扫描进阶

本文面向已经读过[把媒体加入资源库](../features/manage)并希望了解“文件到底经过了哪些步骤”的用户。日常使用不需要手动操作下面的目录或接口。

## 上传会经过哪些阶段

管理页的上传流程由浏览器和 Server 共同完成：

1. **检查扩展名**：浏览器先筛选支持的图片（含相机 RAW）、视频和音频扩展名；Server 收到文件后还会再次验证。
2. **计算指纹**：客户端计算 BLAKE3 指纹，向目标资源库做一次重复项预检。预检只是优化，即使预检请求失败，文件仍会继续上传并由 Server 做最终校验。
3. **传输文件**：不超过 10 MiB 的文件会进入批量上传；大于 10 MiB 的文件会自动创建可恢复的上传会话并分块传输。分块大小和并发数由 Server 的上传配置决定，用户不需要手动拆分文件。
4. **写入暂存区**：完整文件会写入目标资源库的 `.lumilio/staging/incoming/`；分块合并时会先使用 `.lumilio/temp/`。无论哪种方式，都不会直接把浏览器文件写进最终目录。
5. **去重和归档**：Server 再次计算完整指纹；若内容已经存在则返回“重复项”。新文件按资源库策略确定 `inbox/` 下的路径，并创建媒体记录。
6. **后台处理**：原始文件归档后，元数据读取、缩略图、视频/音频 Web 版本和可选分析任务进入后台队列。

上传队列中的“上传中”和“处理中”不是同一个阶段：前者表示字节仍在传输，后者表示原始文件已接收但派生任务尚未结束。网络短暂中断时，分块请求会自动重试；如果仍失败，失败文件会留在管理页中，修复问题后再次点击上传。

## 重复项与重名不是一回事

- **重复项**按内容指纹和文件大小判断。文件名不同但内容完全相同，也会被识别为重复项。
- **重名文件处理**只在新文件需要写入 `inbox/`、而目标路径已经有同名文件时生效。`rename`、`uuid` 和 `overwrite` 是创建资源库时保存的策略，创建后不能修改。

因此，不要为了改变文件名而反复上传相同内容；先确认管理页选择的是正确的目标资源库。

## 扫描的范围和排除规则

手动扫描从资源库根目录递归遍历，但会跳过：

- `.lumilio/` 及其所有子目录；
- `inbox/` 及其所有子目录；
- 不受支持的扩展名、非普通文件和不安全的相对路径。

扫描发现的新文件会在原位置登记，不会搬到 `inbox/`。如果数据库已有同一路径且大小、修改时间没有变化，扫描会跳过它；对于自由区中已登记的文件，如果它被移动到新路径，扫描会用 BLAKE3 指纹和大小尝试匹配原记录，并更新路径而不是创建第二条记录。

当数据库中有记录、磁盘上却找不到对应文件时，扫描会把记录标记为已删除。只有在完整遍历成功时才会执行这一步；遇到权限错误等部分遍历，Lumilio 会保留已有记录，避免一次不完整扫描造成误删。

周期性扫描对刚写入的文件有稳定期，可能会等下一轮再处理；管理页的手动扫描不使用这个等待期。无论哪种方式，都应在复制文件完成后再发起扫描，避免扫描到未写完的文件。

## 暂存区出现文件意味着什么

| 位置 | 含义 | 建议 |
| --- | --- | --- |
| `.lumilio/staging/incoming/` | 正在接入或等待提交的文件 | 不要移动、重命名或删除；先观察队列 |
| `.lumilio/staging/failed/` | 接入或提交失败、等待恢复的文件 | 先查看管理页/状态页错误，确认存储可写后重试 |
| `.lumilio/temp/` | 分块合并等临时文件 | 不要手动清理正在运行的任务 |

提交成功后，文件会离开 `incoming/` 并进入 `inbox/`。暂存区的目录结构、回收站和存储策略示例见[存储细节](./storage-details)。

## “扫描不到”时按顺序检查

1. **路径**：文件是否真的位于当前资源库，而不是另一个挂载点或另一个资源库。
2. **受保护目录**：文件是否误放在 `inbox/` 或 `.lumilio/`。
3. **扩展名**：扩展名是否在管理页的**支持的格式**列表中；扫描不会只根据文件内容猜测类型。
4. **挂载和权限**：Server 容器是否看到了 bind mount，运行 Lumilio 的账户是否有读取权限；Desktop 存储位置是否仍在线。
5. **文件是否写完**：大批量复制完成后再扫描；周期性扫描可能还在稳定期内。

## “上传失败”时按顺序检查

1. 目标资源库是否显示离线或需要处理。
2. 资源库目录及 `.lumilio/` 是否可写、磁盘是否有剩余空间。
3. 浏览器到 Server 的连接是否稳定；大文件优先让可恢复分块会话继续，不要同时重复开启多批上传。
4. 失败文件是否仍保留在管理页的待上传队列中；修复问题后重新点击**上传**。
5. 若原始文件已接入但派生任务失败，转到[状态页](../features/monitor)查看具体队列错误，不要重新扫描 `inbox/`。

::: danger 不要用文件管理器“修复” Lumilio 的工作目录
`.lumilio/`、`inbox/` 和 `.lumiliorepo` 属于 Lumilio 的工作区和身份标记。手动移动或删除其中的文件，可能使数据库、资源库身份和实际文件互相不一致。需要改变目录或迁移资源库时，请按[资源库与挂载流程](../introduction/repositories)操作。
:::

# 相册与合集进阶

本文补充[相册与合集](../features/collections)中不需要每天记住的实现细节。它适合排查“相册计数和网格不一致”“同名标签出现两次”或“地图上的行程和预期不同”等问题。

## 合集视图的共同规则

合集页显示的是几种不同类型的关系：

| 视图 | 关系的来源 | 是否由用户直接维护 |
| --- | --- | --- |
| 相册 | `album_assets` 成员关系 | 是，可以添加、移除和删除相册 |
| 文件夹 | 资源库相对路径的前缀 | 否，随文件路径和扫描结果变化 |
| 标签 | `(标签名称, 来源)` 关联 | 手动来源可以维护，AI 来源由分类器维护 |
| 人物 | 人脸聚类 | 可以命名、隐藏和修正，但聚类本身由分析产生 |
| 地点 / 行程 | GPS、地点聚类和拍摄时间 | 否，是临时计算出的浏览视图 |
| 事件 | 时间、地点和事件成员关系 | 自动生成，也允许在详情页人工修正 |

这些视图不会复制原始文件。扫描、元数据读取、人脸识别或分类任务完成后，派生视图可能变多、变少或改变封面。

## 资源库范围如何叠加

`图库范围`保存在浏览器偏好中，而不是当前页面 URL。合集列表通常把选中的资源库 ID传给查询；选择**全部资源库**时不传具体 ID。

专题详情页还会有一个固定约束，例如 `album_id`、`folder_path`、`tag_name` 或 `person_id`。浏览器会把当前资源库范围与这个约束一起发送，因此：

- 相册本身可以包含多个资源库的媒体；选择具体资源库时，网格只显示该资源库中的成员，选择全部资源库才显示完整成员；
- 文件夹详情已经包含资源库 ID，所以页面不会再显示一个可以改变它的范围选择器；
- 标签、人物和事件详情仍可能显示范围选择器，切换范围只改变当前网格结果，不会重命名或拆分实体。

相册详情头部的成员数来自相册元数据，而网格还会叠加当前范围、筛选和堆叠规则。选择了具体资源库或额外筛选后，头部数字和当前看到的项目数不同是正常的。

## 相册的创建、分页和删除

相册列表每次最多请求 60 个相册，继续点击**加载更多**才会请求下一批。列表查询会按当前资源库范围检查相册成员或封面媒体是否可见，因此某个相册可能在“全部资源库”出现，在一个既没有其成员、封面也不属于该资源库的范围中不出现。

新建相册的 Web 表单要求名称非空，并要求在创建模式下选择封面；描述可选。编辑模式可以保留原封面，只更新名称、描述、类型或重新选择封面。相册类型有普通相册和**生物图鉴**相册；后者在详情页可以点击**生物图鉴识别**，把该相册成员重新加入 BioCLIP 识别队列。它是后台任务，不会立即把结果写回所有标签。

相册列表的删除是相册级操作，前端会对每个选中的相册分别提交删除请求。数据库中的成员关系会随相册删除而清理，但被相册引用的媒体记录和原始文件不会因此删除。相册详情页隐藏了“删除媒体”动作，详情页的**从当前相册移除**只删除成员关系。

::: warning 批量删除相册不是批量删除媒体
确认框中的对象是“相册”。如果你的目标是移入回收站，应该回到资源库浏览页选择媒体，并确认“受影响资源”数量，而不是在相册列表中删除相册。
:::

## 文件夹详情的路径语义

文件夹没有独立的文件夹 ID。前端把“资源库 ID + 资源库相对路径”编码进 URL；绝对主机路径不会显示在页面中。

文件夹列表请求的是某个父路径的**直接子目录**，但每个卡片的媒体数量、日期范围和封面会递归统计子目录。打开文件夹详情时，查询条件是：

```text
repository_id = 当前资源库
folder_path = 当前相对路径
folder_recursive = true
```

因此详情页包含当前目录及其后代目录。它不是一个可以脱离文件系统独立存在的合集；扫描检测到路径移动后，原文件会在新的文件夹视图中出现。存储路径、`inbox/` 和受保护目录的规则见[存储细节](./storage-details)与[导入与扫描进阶](./ingest-details)。

## 标签来源和同名标签

标签列表按 `(tag_id, source)` 统计使用数量和封面。当前界面的来源筛选是：

- **手动**：来源值为 `user`，由用户在媒体详情或批量操作中添加，可以在详情面板中移除；
- **AI**：界面筛选值为 `zeroshot`，由零样本分类器写入；重新处理时可能被分类器替换；
- **全部**：不限制来源，可能包含其他系统或模型来源。

标签详情把标签名称和来源一起放进路由，并以 `tag_name + tag_source`作为固定查询条件。于是“海边 / 手动”和“海边 / AI”是两个不同的浏览入口，即使显示名称相同。标签详情的固定条件不能在筛选面板中清除；要换标签或换来源，应返回标签列表。

## 人物、地点和事件的派生数据

### 人物

人物列表默认隐藏 `is_hidden` 人物，**全部**选项才会把它们列出。隐藏只影响默认人物网格，不会删除媒体、人脸或人物关联。人物实体可以跨资源库存在；详情网格仍会叠加当前资源库范围。人物名称、确认状态和人脸计数来自人物记录，后台重新聚类后可能变化。人物编辑窗口中的**人脸**面板使用不带资源库范围的查询，默认每次加载最多 60 张人脸并显示总数；当前面板没有独立的“加载更多”按钮。移动、移除或合并人脸前，要注意它可能影响其他资源库。

### 地点和行程

地图只请求带 GPS 纬度和经度的媒体。地图移动或缩放时，页面按当前视口边界加载点；点击点可以打开媒体详情。合集首页的行程卡片不是数据库中的独立实体，而是前端根据地点聚类和时间重新计算：同一城市的媒体按拍摄时间排序，时间间隔超过 3 天会分段，少于 5 项媒体的分段不会显示为行程。行程详情再用一个带少量边距的地理框和开始/结束时间筛选媒体，所以它是近似的回顾视图，不应当当作人工编辑后的相册。

### 事件

事件列表使用游标分页，每次请求最多 50 个事件。事件由时间和地点算法重建；详情页的重命名、设置封面、添加、移除、合并和拆分属于人工约束。页面提示“等待事件重新构建”时，说明这些约束已记录，但自动分组尚未完成下一次发布。事件成员移除只把媒体排除出该事件，媒体仍留在资源库中。

## 工具视图的范围

- **喜欢**使用 `liked = true` 约束，并隐藏普通的“设置喜欢”动作；在此页的批量菜单中可取消喜欢。
- **重复项**按资源库加载候选组，可在待处理、已合并和已忽略之间切换。合并时选择保留项，其余候选会进入软删除流程；“视觉相似”不等于内容完全相同，提交前应逐项检查。
- **回收站**是软删除后的处理入口，不是备份。清空或永久删除的行为应按回收站页面的确认提示执行。
- **文档、收据、插画**等智能分类页本质上是 `tag_source = zeroshot` 的固定标签查询，分类器不可用或尚未完成时可能为空。
- **分享链接**和相册、人物、事件详情中的分享按钮使用不同的来源引用；撤销链接不会收回接收者已经下载的文件。

## 遇到结果不一致时

按这个顺序检查：

1. 当前**图库范围**是否和预期一致；这个设置不在 URL 中。
2. 详情页是否叠加了固定约束（相册、文件夹、标签或事件）。
3. 是否把头部总数与当前筛选后的网格数作了比较；两者统计层级可能不同。
4. 媒体是否刚导入、扫描或完成 AI 任务；派生索引仍在后台队列时，合集不会立即稳定。
5. 是否把“解除成员关系”误认为“删除媒体”；先查看确认框中的对象和受影响数量。

如果问题涉及 URL 中的筛选条件、堆叠展开或批量请求失败，请继续阅读[浏览与搜索进阶](./browse-details)；如果问题涉及路径、挂载或扫描，请阅读[存储细节](./storage-details)和[导入与扫描进阶](./ingest-details)。

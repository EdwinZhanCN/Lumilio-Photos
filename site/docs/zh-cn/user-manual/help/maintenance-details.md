# 设置与状态进阶

这篇内容用于排障和管理员维护。日常操作请先看[账户、用户与偏好](../features/settings)和[检查任务与服务状态](../features/monitor)。

## 哪些设置保存在哪里

| 设置 | 所有者 | 影响范围 |
| --- | --- | --- |
| 语言、地区、主题、资源页面布局、健康检查间隔 | 当前浏览器的本地偏好 | 只影响当前浏览器或设备 |
| 个人资料、密码、TOTP、通行密钥 | Server 账户数据 | 当前账户的登录和显示 |
| 用户角色、活跃状态、云凭据 | Server 数据库与凭据目录 | 当前账户或整个部署 |
| AI/ML 开关、备份计划 | Server 系统设置 | 所有使用该 Server 的用户 |
| 存储位置、Lumen AI Hub、监听和证书 | Desktop 控制面板或完整 TOML | Desktop/Server 运行时 |

Web 页面保存服务器设置时使用“草稿 → 保存”的流程；刷新页面前未保存的修改不会生效。运行时信息标签是只读投影，不能当作环境变量编辑器。

## 备份的实际边界

应用内数据库备份写入配置的 backups 目录，保存 SQLite 目录数据和应用版本信息。它不包含资源库中的原始媒体、缩略图缓存、Lumen 模型或云端文件。完整恢复至少需要：

1. 原始媒体所在的资源库目录；
2. 与之匹配的 SQLite 数据库备份；
3. Server 的密钥、完整 TOML 和必要的凭据文件。

点击**恢复**前，Server 会在服务端替换当前数据库；成功后 Web 应用会主动重新加载。不要在恢复过程中关闭容器或删除媒体目录。恢复失败时服务会尝试回滚到之前的数据库，但仍应保留外部备份。

## 读懂队列状态

状态页的“问题”不是单一错误计数：`retryable` 表示任务还会重试，`cancelled` 和 `discarded` 表示任务已停止。展开错误样本时，重点比较多个任务是否共享同一原因，例如：

- 所有任务都出现“permission denied”：先查挂载和目录权限；
- 只有视频转码失败：查 FFmpeg、硬件加速和单个媒体编码；
- Lumen AI 相关任务全部等待：查能力页中的节点发现和模型就绪状态；
- 队列总数在增长但完成数不变：记录最早剩余时间和平均等待时间，再检查日志。

复制的诊断文本可以安全地交给维护者，但不要把公开分享 URL、API Key 或云凭据粘贴到错误报告中。

## Desktop 与 Server 的诊断入口

Desktop 控制面板可以分别查看 Server 和 Lumen AI 的阶段、错误和受限日志尾部。Server 部署则先看容器日志和 TOML 中的 `storage.path`、`storage.backups_path`、`lumen.*` 等值；修改完整清单后重启，不能只依靠 Web 运行时信息进行热改。

::: danger 先保留证据再修复
在重启、恢复数据库或移动存储目录前，保存队列名、时间、错误样本、资源库名称和当前配置指纹。这样即使修复失败，也能判断问题发生在导入、派生处理、ML 节点还是数据库层。
:::

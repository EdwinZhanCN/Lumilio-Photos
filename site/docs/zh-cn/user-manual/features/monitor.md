# 检查任务与服务状态

<DocPath :items="['侧边栏', '状态']" />

**状态**页（`/server-monitor`）是管理员的诊断入口，不是普通用户的媒体浏览页。它把后台处理拆成三个标签：**处理活动**、**ML**和**能力**。先判断任务是否仍在前进，再决定是否需要重试或修改配置。

## 先看“处理活动”

处理活动每 5 秒刷新一次，顶部的统计卡片显示：

- **活动任务**：可领取、已安排和正在运行的任务总数；
- **已完成**：已经完成的任务数和成功率；
- **问题**：可重试、已取消或已丢弃的任务数。

下方按队列列出导入、元数据、预览图、转码、堆叠、重复项、地点和 ML 等工作。每个队列还会显示总数、已处理、剩余、需关注、平均处理时间和平均等待时间。

| 状态 | 含义 | 建议 |
| --- | --- | --- |
| 空闲 | 当前没有待处理项目 | 不需要操作 |
| 等待处理 / 处理中 | 仍有剩余项目，且队列在前进 | 等待，不要重复上传或扫描 |
| 已稳定 | 曾经处理过，目前没有剩余项目 | 继续检查媒体结果 |
| 需关注 | 存在可重试、取消或丢弃的任务 | 展开错误样本，先修复共同原因 |

展开**需关注**的队列可以查看最多 5 条错误样本，包括任务类型、尝试次数和最后错误。点击**复制错误**会复制一段可提交给管理员或开发者的诊断文本；它不包含原始媒体内容。

## 用“ML”判断结果是否只是尚未生成

ML 标签页按当前选择的**资源库范围**显示图像总数、视频总数、待处理任务和各任务覆盖率。当前可见的任务包括图像语义、视频语义、OCR 和人脸；BioCLIP 也会显示已有统计，但其重建入口位于对应的生物图鉴相册。

对某项任务点击**重建索引**时，可以选择：

- **仅补缺**：只处理没有该索引的媒体，适合首次排队后补齐；
- **全量重建**：重新处理所有媒体，适合模型或预处理版本变化后的维护。

确认框会显示预计数量，并提醒设置中已禁用的任务。关闭 ML 开关不会删除已有索引，但重建请求也不会让禁用的任务重新运行。

## 用“能力”区分“未启用”和“不可用”

能力标签页每 5 秒刷新一次，显示：

- 已发现和活跃的 ML 节点数量；
- 语义、BioCLIP、OCR、人脸等任务分别是**已启用**还是**可用**；
- Lumilio Agent 是否启用、是否配置提供方和模型。

“已启用但不可用”通常表示节点没有启动、连接失败或模型尚未就绪；“未启用”则是设置选择，不等于故障。缩略图、文件名和基础浏览不依赖这些可选 ML 任务。

## 常见现象的处理顺序

1. **媒体已经出现，缩略图或 Web 播放版本还没有**：先看队列是否仍在运行；
2. **只有人物、OCR 或语义结果缺失**：看对应任务的能力和覆盖率，不要重复导入原始文件；
3. **失败数持续增长**：先确认存储位置在线、目录可写、磁盘有空间，再展开错误样本；
4. **队列长期没有进展**：记录队列名、错误文本、时间和受影响资源库，再检查 Desktop 控制面板或 Server 日志；
5. **侧边栏显示离线**：Desktop 检查控制面板中的 Server；Server 部署联系维护者检查容器、Compose 挂载和反向代理。

::: danger 不要用“反复重启”代替诊断
重启前先保存错误样本和时间。反复重启可能掩盖路径不可写、磁盘断开、节点未发现或模型下载失败等共同原因，也会让排队任务更难判断是否真的前进。
:::

普通用户没有状态页权限时，把具体媒体、发生时间和界面错误交给管理员；不要通过重复上传、重复扫描或全量重建来试探。

Desktop 控制面板的阶段状态、日志范围和 Server 重启边界见[设置与状态进阶](../help/maintenance-details)。

# 检查任务与服务状态

**状态**页（`/server-monitor`）是管理员的诊断入口，三个标签：**处理活动**、**ML**、**能力**。先判断任务是否还在前进，再决定要不要干预。

## 处理活动：任务是否在前进

顶部统计：活动任务、已完成（含成功率）、问题（可重试/已取消/已丢弃）。

| 状态 | 含义 | 建议 |
| --- | --- | --- |
| 空闲 | 没有待处理项 | 无需操作 |
| 等待/处理中 | 有剩余且队列在前进 | 等待，别重复上传或扫描 |
| 需关注 | 有可重试/取消/丢弃的任务 | 展开错误样本，先修共同原因 |

展开队列可查看最多 5 条错误样本；**复制错误**会生成可提交给维护者的诊断文本，不含媒体内容。

## ML：结果只是还没生成吗

按资源库范围显示各任务（语义、视频、人物、OCR、BioCLIP）的图像/视频总数、待处理数和覆盖率。

- **仅补缺**：只处理没有该索引的媒体；
- **全量重建**：重新处理全部媒体（模型或预处理版本变化后使用）。

关闭的开关不会删除已有索引，但重建也不会让禁用任务重新运行。

## 能力：未启用还是不可用

- 已发现/活跃的节点数量；
- 各项媒体理解能力是**已启用**还是**可用**；
- Lumilio Agent 是否启用、是否已配置提供方和模型。

**「已启用但不可用」= 节点没启动/连不上/模型未就绪；「未启用」= 设置选择，不是故障。** 缩略图、文件名和基础浏览不依赖这些能力。

## 常见问题的处理顺序

1. 媒体已出现但缩略图/播放版本没有 → 看队列是否仍在运行；
2. 只有人物/OCR/语义结果缺失 → 看对应能力和覆盖率，不要重新导入原件；
3. 失败数持续增长 → 先确认存储在线、目录可写、磁盘有空间；
4. 队列长期不前进 → 记录队列名、错误、时间、资源库，再查控制面板或 Server 日志；
5. 侧边栏显示离线 → Desktop 查控制面板；Server 查容器、挂载和反向代理。

::: danger 不要用反复重启代替诊断
重启前保存错误样本和时间。反复重启会掩盖磁盘断开、节点未发现、模型下载失败等共同原因。
:::

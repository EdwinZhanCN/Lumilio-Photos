# 浏览与搜索进阶

本文补充[浏览、筛选与批量操作](../features/assets)中不需要每天记住的细节。遇到“为什么结果数量不一致”“为什么堆叠只显示一个项目”或“批量操作影响了更多资源”时，可以从这里开始排查。

## 页面状态保存在哪里

资源库页把查询条件写入当前 URL。下列操作会更新地址栏，因此刷新页面或复制链接时可以保留：

- 搜索文字；
- 排序方式（拍摄时间或最近添加）；
- 类型、构成、堆叠、评分、喜欢状态、文件名、日期、位置、相机、镜头和标签筛选。

资源库范围、网格布局和紧凑布局列数属于浏览器偏好，保存在本地存储中，不会写进资源库页 URL。分享链接时应同时说明范围；接收者如果打开的是**全部资源库**，结果数量可能与发送者不同。

选择状态也不是 URL 状态。选择模式只在当前浏览页面的内存范围内工作，离开页面、切换到另一个独立的浏览上下文或刷新后，不应假定选择仍然存在。

## 普通浏览和搜索不是同一种结果

### 普通浏览

没有搜索文字时，页面调用资源库列表查询：

- 每次请求最多加载 50 个浏览项目，滚动到底部再加载下一批；
- 请求使用 `stack_mode=collapsed`，堆叠会合并成一个展示行；
- 未堆叠的逻辑媒体项各占一行；
- 日期分组使用当前排序，并结合查看者时区显示“今天、昨天、本周”等分组。

因此，标题栏看到的项目数量是展示层数量，不一定等于磁盘文件数量，也不一定等于数据库中的全部资源文件数量。

### 带搜索文字的浏览

输入非空搜索文字后，页面切换到搜索查询：

- 结果始终按逻辑媒体项平铺，不使用堆叠折叠；
- 服务器先生成一个融合结果集，再把它分成按相关性排列的**最佳结果**和按当前排序展示的**结果**；
- 当前 Web 界面最多展示 9 个最佳结果，完整结果仍会按分页继续加载；
- 搜索结果中的一个逻辑媒体项不会因为它属于堆叠而在结果中变成一个堆叠行。

搜索融合的来源可能包括文件名、OCR文字识别、地点和图像语义分析向量。图像语义分析、OCR文字识别或地点索引不可用时，服务器会尽量退回文件名匹配，并在响应中标记降级；页面会显示“图像语义分析暂不可用”的提示。启用或修复相关索引后，重新输入搜索词或刷新页面即可再次请求。

::: tip “最佳结果”不是额外的一组媒体
最佳结果是完整搜索结果集的一个子集，用于快速确认相关项目。它不会把同一个逻辑媒体项复制成两份；选择或打开时，页面会按项目 ID 去重。
:::

## 筛选条件的组合规则

Server 会把每个已启用的筛选条件放在同一个查询中，条件之间按“同时满足”处理。例如，启用“视频”“已喜欢”和“5 星”后，结果必须同时满足这三项。

### 标签、构成和堆叠

- 选择多个标签时，媒体必须同时拥有所有选中的标签；重复标签会在发送前去重。
- “媒体构成”读取逻辑媒体项的组成事实，`JPEG+RAW`、`RAW 未配对`和“实况媒体”不是简单的扩展名筛选。
- “连拍”和“手动堆叠”是堆叠类型；选择任一类型已经隐含“已堆叠”。“未分组”与类型组合会被拒绝，界面会在提交前清理这种组合。

### 文件名和日期

文件名筛选作用于逻辑媒体项的组成文件：只要其中一个组成文件满足条件，该媒体项就可能匹配。四种操作分别是包含、匹配、开头是和结尾是；“匹配”不是正则表达式入口，不要把正则语法当成通用规则。

日期输入使用查看者时区解释日期，并包含起止边界。为了避免只填一端时产生歧义，建议按完整日期范围填写“从”和“到”。排序中的“拍摄时间”会在缺少拍摄时间时回退到加入时间。

### 位置

位置筛选使用北、南、东、西四个坐标定义矩形范围，只匹配带有 GPS 纬度和经度的媒体。地图按钮会用中心点和半径换算边界框；跨越经度 ±180° 的范围也可以由服务器按东西边界关系处理。

### 专题视图的锁定条件

相册、人物、事件、文件夹、标签和其他专题页面会把固定条件作为查询约束，再叠加用户筛选。固定字段在筛选面板中显示为锁定状态，重置筛选也不会移除它们；要改变范围，应返回专题入口，而不是尝试编辑锁定字段。

## 批量选择的两个计数

批量菜单同时使用两种计数：

1. **已选择项目**：网格中被选中的逻辑媒体项或堆叠行；
2. **受影响资源**：真正传给批量请求的资源 ID 数量。

普通未堆叠项目通常是一对一。选中一个堆叠行时，批量动作会展开该堆叠的全部成员，因此确认窗口可能显示“已选择 1 项，将影响 7 个资源”。这项展开适用于评分、喜欢、标签、相册、下载、删除和堆叠等动作。

键盘选择也有范围边界：**Ctrl/Command + A**只选择当前已经加载到网格中的项目，不会为了选择全部结果而自动把未加载的分页全部拉取。需要处理大量结果时，先用筛选缩小范围，再分批滚动和执行动作。

## 批量动作的执行边界

- 评分、喜欢、标签、加入相册和删除会针对每个受影响资源发送独立请求；它们不是一个跨资源的数据库事务。
- 某个请求失败时，其他已经成功的请求不会自动回滚。看到失败提示后，应重新筛选并检查结果，而不是立即重复整批操作。
- **下载全部**在不超过 10 个资源时逐个触发浏览器下载；超过 10 个资源时请求服务器生成 ZIP。浏览器可能拦截连续下载，也可能因为 ZIP 生成时间较长而稍后才出现文件。
- **移入回收站**使用普通删除接口，文件会进入资源库的软删除流程；这不等同于清空回收站或永久删除。
- 主资源库页的**分享**动作只负责把受影响资源 ID 交给分享表单；标题、有效期、是否允许下载和是否包含原始文件仍需在表单中确认。

::: warning 先做小批量验证
第一次对带 RAW、实况媒体或大堆叠执行标签、下载或删除时，先选一个小范围检查结果。确认“已选择项目”和“受影响资源”符合预期后，再扩大筛选范围。
:::

## 性能和排障提示

| 现象 | 优先检查 |
| --- | --- |
| URL 打开后结果不同 | 对方的**图库范围**是本地偏好，不在 URL 中；先切换到同一个资源库 |
| 筛选后数量突然变少 | 多个条件是同时满足；检查标题栏中的筛选标签，逐个移除 |
| 堆叠看起来少于预期 | 主浏览默认折叠堆叠；查看堆叠数字，或使用堆叠筛选 |
| 搜索结果没有“最佳结果” | 结果集不足以形成独立展示区，或语义增强不可用；继续看“结果”区 |
| 搜索提示降级 | 到[状态页](../features/monitor)查看图像语义分析、OCR文字识别、视频语义等任务是否已完成 |
| 滚动时才出现更多项目 | 这是分页和虚拟化的正常行为；等当前批次加载完成再继续滚动 |
| 批量动作后部分项目未更新 | 批量请求按资源逐个执行；重新筛选并检查失败提示，必要时缩小范围重试 |

如果问题只出现在“刚导入”的媒体上，先阅读[导入与扫描进阶](./ingest-details)；如果问题涉及原始文件路径、堆叠成员或回收站文件，再阅读[存储细节](./storage-details)。

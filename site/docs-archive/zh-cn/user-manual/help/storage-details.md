# 存储细节

本文补充[理解资源库与原始文件](../introduction/repositories)中省略的实现细节，面向希望深入了解存储行为的用户。

## 存储策略

创建资源库时选择存储策略，它决定**上传和云导入**的文件在 `inbox/` 中如何排列。扫描不受影响——扫描登记的是文件当前所在路径。

::: warning 创建后不能更改
当前版本不提供资源库配置更新或删除操作。创建前请确认名称、存储策略和同名冲突处理方式。
:::

| 策略 | 布局 | 说明 |
| --- | --- | --- |
| **date**（默认） | `inbox/年/月/<文件名>` | 按上传日期归档，例如 `inbox/2026/01/IMG_001.jpg` |
| **flat** | `inbox/<文件名>` | 所有文件直接放在 inbox 根目录 |
| **cas** | `inbox/aa/bb/cc/<完整哈希>.<扩展名>` | 根据内容哈希分层存放，去重友好 |

`date` 策略按**上传日期**而非拍摄日期分组。`cas` 策略取 BLAKE3 完整哈希的前 6 位分成三层 2 字符目录，例如 `inbox/a1/b2/c3/a1b2c3...full_hash.jpg`。

## 同名冲突处理

遇到同名文件时的行为由创建资源库时选择的策略决定。推荐默认是**同名冲突时安全重命名**；**任何策略都不会替换已有原件**。

| 策略 | 行为 |
| --- | --- |
| **rename**（管理页默认） | 同名冲突时追加 `(1)`、`(2)` 等，超过 999 个回退为时间戳；适合人工整理的资料库 |
| **uuid** | 追加 8 位短 UUID 后缀，例如 `photo_abc12345.jpg`；适合机器管理的仓库（自动化导入、脚本同步） |

同名同内容会先被识别为重复项（不会写入第二份）；只有内容不同才需要重命名。

## .lumilio 目录结构

每个资源库内的 `.lumilio/` 目录由 Lumilio 管理，包含派生文件和系统工作区：

| 路径 | 权限 | 用途 |
| --- | --- | --- |
| `.lumilio/assets/` | 0755 | 缩略图、转码和人脸派生文件 |
| `.lumilio/assets/thumbnails/{small,medium,large}/` | 0755 | 三种尺寸缩略图 |
| `.lumilio/assets/videos/web/` | 0755 | Web 可播放视频转码 |
| `.lumilio/assets/audios/web/` | 0755 | Web 可播放音频转码 |
| `.lumilio/assets/faces/` | 0755 | 提取的人脸裁切图 |
| `.lumilio/sidecars/` | 0755 | 工作室非破坏性编辑记录（`.lumilio-sidecar`） |
| `.lumilio/staging/incoming/` | 0700 | 正在接入的文件 |
| `.lumilio/staging/failed/` | 0700 | 接入失败、等待处理的文件 |
| `.lumilio/temp/` | 0700 | 临时处理文件（如分块合并） |
| `.lumilio/trash/` | 0755 | 软删除的媒体 |
| `.lumilio/logs/` | 0755 | 该资源库的操作日志 |

`.lumilio/` 和 `inbox/` 前缀都是受保护路径，扫描器不会处理这些目录下的文件。

## 暂存管道（上传与云导入）

上传和云导入的文件不会直接写入 `inbox/`，而是经过以下步骤：

1. 文件写入 `.lumilio/staging/incoming/`（分块上传先在 `temp/` 合并，再进入暂存区）。
2. 计算 BLAKE3 内容指纹，与已有资源比对去重。
3. 根据存储策略计算 `inbox/` 中的目标路径。
4. 创建数据库记录（标记为"已准备"状态）。
5. 将文件从暂存区移动到 `inbox/` 目标路径（同文件系统优先硬链接，跨文件系统回退为复制后删除源文件）。
6. 更新数据库记录，入队元数据读取、缩略图生成等后续任务。

如果提交失败，暂存文件会被移到 `.lumilio/staging/failed/`，数据库记录标记为可恢复。重试时可以从失败目录恢复。

## 扫描如何工作

扫描遍历资源库目录（排除 `.lumilio/` 和 `inbox/`），对发现的文件：

1. 跳过不支持的文件扩展名。
2. 计算 BLAKE3 内容指纹。
3. 如果同一路径已存在且内容未变，跳过。
4. 如果内容未变但路径变了（文件被移动），更新数据库中的路径，不移动文件。
5. 如果数据库中有记录但文件不存在，标记为软删除。
6. 新文件创建数据库记录并入队后续任务。

扫描器还会对周期性扫描设置一个"稳定期"——刚写入的文件如果在稳定期内，会等到下一次扫描再处理，避免处理正在写入的文件。手动扫描不设稳定期。

## 软删除与回收站

普通删除是软删除：文件被重命名移到 `.lumilio/trash/`，同时写入一个 JSON 元数据文件记录原始路径、删除时间和原因。数据库中保留记录但标记为已删除。

恢复时，文件从回收站还原到原始路径，数据库记录恢复为活跃状态。永久删除和清空回收站才会真正删除文件。回收站会按可配置的时间自动清理过期的已删除文件。

## 离线与重定位

外接磁盘或网络卷断开后，存储位置及其资源库会显示为离线。Lumilio 保留其身份和浏览记录，但在重新连接前拒绝写入操作，不会在另一块磁盘上静默创建同名目录。

当同一 `.lumilioroot` 因磁盘挂载点或 Windows 盘符变化出现在新路径时，在 Desktop 控制面板重新添加该目录并选择"重新连接到此处"。位置内资源库的相对路径会随之更新。

### 身份冲突

如果同一个 `.lumilioroot` 或 `.lumiliorepo` 身份（UUID）已经登记在另一条路径，Desktop 会要求明确选择：

- **作为移动后的位置**：原资源库换了磁盘、挂载点或盘符，数据库路径指向新位置。
- **作为副本登记**：这是需要独立身份的复制目录，Lumilio 会为它生成新的 UUID。

Lumilio 不会仅根据旧路径是否在线来猜测"移动"还是"复制"。

## 内容指纹

Lumilio 使用 **BLAKE3** 为媒体计算内容指纹（64 位十六进制哈希）。它的作用包括：

- 上传前预检查，识别已存在的相同内容。
- 辅助重复项分析。
- `cas` 存储策略的目录分层依据。
- 扫描时检测文件移动。

内容指纹本身不会产生副本，也无法在原件已损坏或丢失后将其恢复。对于大于 100 MB 的文件，Lumilio 会额外计算一个快速指纹（文件大小 + 首尾各 1 MB 的哈希），仅用于预检，不作为内容身份。

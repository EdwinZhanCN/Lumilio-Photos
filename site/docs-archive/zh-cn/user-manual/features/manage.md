# 把媒体加入资源库

<DocPath :items="['侧边栏', '管理']" />

**管理**页有两个区域：上方是上传区，下方是资源库卡片。上传区把浏览器中选择的文件接入当前资源库；资源库卡片用于扫描已在服务器上的文件、创建资源库和执行维护操作。

## 先选择合适的导入方式

判断标准只有一个：**运行 Lumilio 的主机能不能直接读取文件**。

| 文件现在在哪里 | 使用方式 | 文件最终在哪里 | 适合的情况 |
| --- | --- | --- | --- |
| 当前电脑、手机或平板，浏览器可以选择到 | **上传** | `inbox/`，由资源库策略归档 | 少量文件、跨设备导入 |
| Desktop 已授权的位置，或 Server 已挂载的资源库目录 | **扫描** | 保留在原来的自由区路径 | 大批量导入、希望自己管理目录 |
| 已连接的云服务凭据 | **云导入** | `inbox/`，由资源库策略归档 | 从云端导入；当前 iCloud 仍是实验性功能 |

浏览器选择文件只会把选中的文件内容发送给 Lumilio，**不会授权服务器任意读取浏览器设备上的目录**。关于存储位置、资源库和 Desktop/Server 的差异，请先阅读[理解资源库与原始文件](../introduction/repositories)。

## 开始前：确认上传目标

1. 打开**管理**页。
2. 在上传区的**上传目标**下拉框中选择资源库。
3. 在点击**上传**前再次确认目标；同一批文件会提交到这里选择的资源库。

如果下拉框为空、资源库显示为“离线”或“需要处理”，先不要导入。Desktop 用户检查控制面板中的存储位置；Server 用户检查 Compose 挂载、目录权限和磁盘状态。离线资源库会拒绝写入，不会在其他位置悄悄创建同名目录。

## 方式一：上传浏览器中的文件

### 操作步骤

1. 点击页面标题右侧的**支持的格式**，确认文件扩展名是否受支持。
2. 把文件拖到上传区，或点击**添加文件**选择文件。当前支持图像（含相机 RAW）、视频和音频格式。
3. 检查文件列表和**上传目标**，点击**上传（数量）**。
4. 保持页面打开，直到队列中的项目变为**已完成**、**重复项**或**失败**。大文件会自动使用可恢复的分块上传，不需要手动拆分。

前端会先按扩展名筛选文件，服务器还会再次验证。被判定为不支持的文件不会进入上传队列；请按提示移除或转换后再试。

### 上传结果如何理解

- **已完成**：文件已经通过服务器校验并完成接入任务。
- **处理中**：原始文件已接收，元数据、缩略图、视频或音频派生文件仍在后台生成。
- **重复项**：内容指纹与目标资源库中的现有媒体一致，Lumilio 跳过了第二份内容，不会重复占用存储空间。
- **失败**：该文件未完成接入。失败文件会保留在待上传队列中；修复网络、权限或磁盘问题后，再次点击上传即可重试。

上传成功后，原文件会先进入资源库的暂存管道，再按创建资源库时选择的策略写入 `inbox/`。不要在文件管理器中手动修改 `inbox/`；策略和目录结构见[存储细节](../help/storage-details)。

::: tip 先用小批量验证
第一次接入新相机、手机导出目录或外接盘时，先选择少量文件。确认时间、方向、重复项处理和缩略图都符合预期后，再提交完整资料。
:::

## 方式二：扫描已经位于主机上的文件

扫描不会复制文件，也不会让浏览器选择服务器路径；它会在目标资源库中登记已经存在的文件。

### 准备文件

- 把文件放在目标资源库的**自由区**：即资源库根目录下，除 `inbox/` 和 `.lumilio/` 之外的目录。
- Desktop 需要先在 Desktop 控制面板授权对应的存储位置。
- Server 需要先按[资源库的挂载和创建流程](../introduction/repositories#server)完成 bind mount；容器内的路径必须已经可读。

::: danger 不要把文件放进受保护目录
`inbox/` 由上传和云导入管道管理，`.lumilio/` 保存缩略图、暂存文件、日志等系统数据。扫描器会跳过这两个目录；手动改动还可能造成数据库与实际文件不一致。
:::

### 发起扫描

1. 把媒体放入自由区，并等待文件复制完成。
2. 在资源库卡片右上角打开 **⋯** 菜单，选择**重新扫描**。
3. 如果要扫描所有资源库，点击卡片区域上方的**扫描全部资源库**。
4. 等待操作结束，再到资源库或[状态页](./monitor)查看新媒体和后台处理任务。

扫描只登记支持的媒体扩展名。对于自由区中已经登记的文件，它会尽量识别“同一个文件被移动到新路径”的情况并更新记录，而不是创建第二条媒体记录；删除自由区文件后，扫描会把对应记录标记为已删除，具体行为见[存储细节](../help/storage-details#扫描如何工作)。

## 方式三：云导入

云导入需要已经连接的云凭据。先到[设置](./settings)的**云导入**标签页完成登录和必要的验证，然后按来源选择操作：

- **创建新资源库时导入**：点击**创建资源库**，将来源选择为云端并选择已连接的凭据。资源库创建成功后会自动排队一次导入。
- **已有云资源库再次导入**：在对应资源库卡片的 **⋯** 菜单中选择**从云端导入**。只有已经绑定云凭据的资源库才会显示此项。

云导入的文件和上传文件一样进入 `inbox/`，遵循资源库的存储策略。卡片会显示最近一次导入的状态、已导入数量和失败数量；任务处于“排队”或“运行中”时，重复触发按钮会被禁用。

::: warning iCloud 仍是实验性功能
iCloud 导入依赖 Apple 的非官方网络服务行为，可能需要额外验证，也可能随时失效。使用前请阅读[测试版与可选功能](../introduction/experimental)。
:::

## 创建资源库（管理员）

资源库卡片区域的**添加资源库**（创建资源库）按钮只适合管理员使用。创建时需要一次性确定以下内容：

1. **存储位置**：Desktop 从已在控制面板登记的位置中选择；Server 使用 Compose 已挂载的存储位置。
2. **资源库名称**：普通资源库的名称同时是目录名。只能使用文字、数字、半角空格、`-` 和 `_`，长度为 1–80 个字符，不能以空格开头或结尾；大小写会原样保留。
3. **来源**：本地文件或云端凭据。
4. **文件布局**：
   - `date`：按接入时间写入 `inbox/年/月/`；
   - `flat`：所有接入文件放在 `inbox/` 根目录；
   - `cas`：按内容哈希分层保存。
5. **同名冲突处理**：`rename`（默认，同名冲突时安全重命名并追加序号）或 `uuid`（追加短 UUID）。**任何策略都不会替换已有的原件**。

创建请求会校验名称、目录状态和写入权限，并在失败时立即返回；新资源库不会登记成一个不完整的状态。如果目标目录已经包含有效的 `.lumiliorepo`，Lumilio 会把它作为已有资源库登记；普通的非空目录不能当作新资源库初始化。资源库创建后，当前版本不能修改名称、布局或同名冲突策略，也不能从 Lumilio 中删除资源库。Server 的“先挂载、再创建”顺序和目录名对应关系，请严格按[Server 挂载流程](../introduction/repositories#server)操作。

## 资源库卡片上的维护操作

打开卡片右上角的 **⋯** 菜单，可以看到当前资源库支持的操作：

- **重新扫描**：只扫描当前资源库的自由区；适合刚复制完一批文件后使用。
- **检测堆叠**：为当前资源库运行自动堆叠检测；完成后到[浏览、筛选与批量操作](./assets)查看堆叠结果。
- **扫描重复项**：运行重复项分析；结果在[重复项、喜欢与回收站](./utilities)中处理。
- **重建位置聚类**：重新计算媒体的位置聚类；不会移动原始文件。
- **从云端导入**：仅对已绑定云凭据的资源库显示。

卡片上的资源数量、云导入统计和“离线/需要处理”标记来自服务器当前状态。存储位置不可用时，写入和维护按钮会被禁用；先恢复挂载或权限，再重新执行操作。

## 导入后检查什么

媒体接入和派生处理是两个阶段：原始文件可能已经出现在资源库中，但缩略图、视频/音频 Web 版本、人物或语义结果仍在队列中。遇到以下情况时：

- 队列仍在运行且完成数增加：等待处理，不要重复扫描或重复上传；
- 媒体显示为重复项：确认目标资源库是否正确，通常无需再次导入；
- 失败数持续增加或长时间没有进展：确认磁盘在线、目录可写且空间足够，再到[状态页](./monitor)查看任务错误；
- 扫描结果为 0：确认文件不在 `inbox/`/`.lumilio/`、扩展名受支持，并且文件确实位于当前资源库的挂载路径。

需要查看上传分块、指纹预检、扫描排除规则等实现细节时，请阅读[导入与扫描进阶](../help/ingest-details)。

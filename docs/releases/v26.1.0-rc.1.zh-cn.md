# 流明集 Lumilio Photos 26.1.0-rc.1

rc.1 是流明集的第一个受支持版本。从这个版本开始，数据库、Server 配置、备份，以及媒体目录中的 `.lumilioroot` / `.lumiliorepo` 标记都会由之后的每个版本原地升级。beta 构建写入的数据**不会**迁移；在 beta 之上安装前请先阅读[升级](#升级)。

## 安装前请阅读

- **Desktop 构建只在 CI 运行器上经过自动化验证，没有在实体机器上启动过。** 本次发布的 macOS（Apple Silicon）和 Windows（x64）应用由发布工作流构建，并在 GitHub 托管的 macOS 和 Windows 运行器上通过了 Desktop 自动化测试套件。发布之前，没有任何人在真实的 Mac 或 PC 上启动过 rc.1 的 Desktop 构建。请把 Desktop 当作字面意义上的“候选版本”：保留一份独立的媒体备份，并报告任何与本文不符的行为。
- **rc.1 的 Desktop 没有应用内更新。** 设置 → 更新 会提示“此构建未配置已签名的更新提供方”。新版本需要从 GitHub Releases 页面下载并覆盖安装；应用内更新计划在 rc.2 提供。
- **不支持网络存储。** 位于 NFS、SMB/CIFS、AFP、sshfs、WebDAV 或 Windows 网络驱动器上的存储位置和资源库会被拒绝，并且无法通过确认绕过。流明集运行在 NAS 上、媒体放在本地磁盘上的部署不受影响。

## 新增

### 回收站、缺失与永久删除

- **移入回收站会真正移动文件。** 删除照片或视频时，文件会从你的目录移到所在资源库自己的回收站。恢复会把文件放回原路径，相册、评分、喜欢、标签、描述和人物都保持不变。
- **回收站按资源库划分并会过期。** 管理员可以在“存储”页按资源库打开回收站，所有用户可以在 合集 → 回收站 查看自己的项目。回收站中的文件保留 30 天后永久删除；Docker 部署可在 `server.toml` 的 `repository_trash.retention_days` 中调整，Desktop 固定为 30 天。**永久删除**会立即移除回收站中的文件。
- **重复项处理会释放空间。** 未保留的重复项会移入回收站而不是仅被隐藏；它们过期或被永久删除后，磁盘空间才会真正释放。
- **缺失的文件会被隐藏，而不是显示为损坏。** 文件从磁盘上消失时（拔掉了移动硬盘、在访达或资源管理器里删除了文件），这张照片会从浏览、搜索、相册和“存储”页的计数中消失，并出现在该资源库的**缺失**视图中。相同的文件回来后，照片连同元数据一起恢复。**移除缺失项**会忘记这些缺失文件，不会碰磁盘。
- **在其他应用中编辑文件会保留元数据。** 原地改写文件（包括只改写 XMP 或 EXIF 元数据）后，照片的相册、评分、喜欢、标签、描述和人物都保留，缩略图会重新生成。
- **删除之前创建的备份会恢复到回收站。** 恢复这样的备份后，被删除的文件会出现在回收站中，可以恢复或删除，而不是被报告为缺失。
- **重新打开的资源库会保留它带来的内容。** 打开一个在早先安装中已有回收站、Studio 编辑或未完成上传的资源库时，这些内容不再被搁置到一边。它的回收站会被列出并**保留**：在你恢复、永久删除或选择**按正常保留期保留**之前，这些文件不会自行过期。扫描证实内容后，Studio 编辑会重新关联到对应照片；无法证实的记录，以及未完成的上传和未知文件，会列在“存储”页中该资源库的**恢复清单**里，你可以逐项导出或删除。

### 扫描

- 重新扫描时，每个文件的大小和修改时间会与扫描索引比对；没有变化的文件不会被再次读取，重命名或移动过的文件和目录保留原有身份和元数据，不会重新计算哈希。
- 每个资源库会周期性地完整验证（默认每 300 秒一次；Docker 部署通过 `repository_scan.interval_seconds` 调整），并在平台支持时使用文件系统变化通知。
- “存储”页显示扫描进度和计数、扫描历史，以及每个资源库的**立即扫描** / **取消扫描**。

### 存储页

- 管理员的“存储”页把资源库按存储位置分组，按资源库显示容量、扫描状态和历史，并提供**重命名资源库**、**从流明集中移除**（目录及其文件保留在磁盘上）、**检测重复项**、**检测堆叠**和**下载支持包**。
- **添加资源库前先审核目标位置。** 流明集会评估所选的存储位置和目录（文件系统、是否为可移动卷、权限、已有标记）并列出风险；你需要逐项确认后才会创建资源库，期间磁盘发生变化时会重新审核。不受支持的目标（包括网络存储）会在写入任何内容之前连同原因一起被拒绝。

### 音乐

- 新增**音乐**板块：曲目、音乐专辑、艺人和歌单，播放器停靠栏在你浏览其他页面时继续播放，支持播放队列、喜欢的曲目和全屏歌词。元数据修正不会改写音频文件。
- Lumilio Agent 可以搜索你的音乐、试听曲目，并在你确认后创建或追加歌单。
- 事件只由照片和视频构成；音频归属于音乐。

### 处理活动视图

- 监控 → **处理活动** 把处理流水线的每个阶段显示为一张卡片，列出排队、运行和失败的数量，可以重试失败项并查看该阶段的诊断信息。

### 导出照片

- 查看器和工作室共用一个**导出照片**对话框，格式、质量、尺寸和文件名设置保持一致。

### Lumilio Agent

- 只要服务器还保留会话记忆（闲置两小时内），标签页中的聊天记录在刷新页面后仍然保留，待确认的操作也不会因刷新丢失。

## 修复

- “存储”页按资源库显示的资产数量不正确。
- 完整重建搜索索引时可能在上一轮结果仍在被替换时就报告完成；现在进度直接来自本次重建。
- 对事件的编辑（名称、封面、成员）可能被后台的事件重建撤销。
- 退出登录时只有在会话真正关闭后才打开登录页，不再中途重置登录表单。
- 原件正在播放时网页版转码完成，音频和视频播放不再卡住。
- 服务器读取不到分享链接密钥时会在启动时报告，而不是在第一次分享时失败。

## 已知问题

- **Desktop 应用内更新**不可用；请从 GitHub Releases 下载新版本（计划在 rc.2 提供）。
- **网络存储**上的存储位置和资源库会被拒绝。
- **音频文件内嵌的封面不会显示。** 曲目使用占位图，把音频文件设为相册封面会失败。
- **在不同操作系统之间迁移数据库后，仅大小写不同的重命名可能被当作新文件。** 从 macOS 或 Windows 恢复到 Linux（或反过来）的数据库仍按原系统的规则比较文件名，下次扫描时，一个只改了字母大小写的文件可能被登记为新文件。
- **移除非常大的资源库**会在移除完成前阻塞其他数据库写入。
- **分享相关控件缺少无障碍名称。** 导出对话框中的分享、工作室、添加到相册按钮以及公开分享页中的图块不会被屏幕阅读器朗读。
- **分享的 ZIP 下载始终包含原件**：只要允许下载，即使关闭了“包含原件”选项也是如此。
- **初始化之后注册仍然开放。** 任何能打开登录页的人都可以创建普通用户账户，没有邀请码，也没有关闭注册的开关。不要在没有前置访问限制的情况下把实例暴露到公网。
- **备份只能从服务器的备份目录恢复。** 下载按钮提供的 SQLite 快照只是一份副本，没有上传备份文件进行恢复的入口。
- **云导入**只支持 iCloud，并且是单向导入，不是同步。
- **平台。** Desktop 只发布 macOS Apple Silicon 和 Windows x64 版本；Linux 使用 Docker Server；没有移动端应用。

## 升级

### 从 beta 构建升级

rc.1 不会打开 beta 构建（`v1.0.0-beta.*`、`v26.1.0-beta.*`）写入的数据库、配置或备份；它会把这类文件标明为预发布数据并停止启动。beta 中的相册、人物、评分、事件名称和分享链接不会带到 rc.1。媒体文件和资源库目录不受影响，rc.1 能读取 beta 写入的标记。

1. 如需留作参考，先在 beta 构建中创建一份数据库备份，并独立备份媒体。
2. 停止 beta 构建。把它的应用状态移到别处（Docker：`LUMILIO_STATE` 目录；Desktop：用户应用数据目录下的 `Lumilio Photos` 文件夹）。不要删除媒体目录。
3. 把 beta 的主资源库目录（默认存储位置内的 `primary/`）在同一个存储位置内改名，例如改为 `beta-primary/`。rc.1 的初始化会在 `primary/` 新建主资源库。
4. 安装 rc.1 并完成首次初始化。
5. 在“存储”页把改名后的目录作为已有资源库添加回来，让扫描重新登记其中的文件。beta 使用过的其他资源库按同样方式处理。

### 从 rc.1 开始

- 新版本变更数据库时，启动过程会先在备份目录写入一份 `pre-upgrade-…` 快照（不受保留策略影响，并显示为恢复点），再升级数据库。任一升级步骤失败时，Server 会停止启动并写明失败的步骤和这份快照。
- Server 不会自行改写 `server.toml`。配置格式变化时，启动会停止并提示运行
  `docker compose run --rm lumilio server config upgrade --config /data/app-state/server.toml`，
  原文件保存为 `server.toml.bak`。默认 Docker 配置内置在镜像中，Desktop 会自动升级自身配置，二者都无需此步骤。
- 旧版本会拒绝由更新版本写入的数据库、备份或配置；回退时使用升级前快照。

Desktop 和 Docker 的完整步骤：
<https://docs.lumilio.org/zh-cn/user-manual/admin/upgrade>（中文）和
<https://docs.lumilio.org/user-manual/introduction/upgrade>（English）。
